The table and validation below record the earlier source-only remediation pass. For the subsequent production rollout, restricted runtime identities, browser-based desktop authentication, and current validation boundaries, see [Live security remediation](live-security-remediation.md).

This tracks work against `SECURITY_AUDIT_2026-10-02.md`. The audit remains a record of the October 2 pre-launch state. Source changes and local tests do not update the deployed Firebase project.

| SEC-01 Vite credential access | Vite filesystem access is limited to app, desktop, shared, and dependencies; development hosts bind to loopback. The tracked admin-claim script uses Application Default Credentials. The ignored key was moved outside the checkout into a user-only configuration directory (directory mode 700, file mode 600). | Determine whether the key was ever exposed off-machine; rotate it if exposure is suspected or uncertain. | SEC-02 unverified accounts | Browser registration uses Firebase Auth directly, sends verification mail, and creates profiles in an authenticated transaction.
